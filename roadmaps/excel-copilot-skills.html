Copilot Skills in Excel —
what's coming, and what we do now.

Microsoft is adding a way to teach Copilot in Excel how we do a task — our variance analysis, our reconciliation, our house formatting — so it does it the same way every month instead of guessing. Here's the short version: what it is, what it will look like, and what we should be doing in the meantime.

Where we stand today

We don't have this yet. Custom skills started rolling out to Microsoft 365 Copilot customers mid-2026 and are still arriving tenant by tenant. Ours isn't switched on, and the developer side of it is still labelled preview by Microsoft.

That's fine — the useful work happens before the button appears. Section 4 is the workaround we can run today, and it produces exactly the material a skill will need on day one. Nothing here is wasted effort.

1

What a "skill" actually is

In one line: a written procedure, saved in a file, that Copilot reads before it starts working. Think of it as onboarding notes for a new analyst — except you only write them once.

💬

A prompt is a request

"Summarise this sheet." Great for one-offs. You get a different answer, and a different layout, every time you ask.

📄

A skill is a procedure

Your steps, your column layout, your number formats, your rules about what not to do. Copilot follows them.

👥

And it's shareable

One person writes it, the team uses it. Everyone's variance schedule comes out looking the same.

3

How you'd build one — five steps

You don't need to be technical. A skill is a plain-text file you can write in Notepad. The whole job is describing your own process clearly.

  1. Pick a task you repeat

    Something you do at least monthly, where the output should look identical each time. The June variance schedule, not a one-off query.

  2. Do it once with Copilot and write down every correction

    Every time you have to say "no, put that column here" or "don't round that" — that's a line in your skill. The corrections are the content.

  3. Write it up as steps, output, and don'ts

    Three headings is all it takes: the steps to follow, exactly what the finished sheet should look like, and the mistakes to avoid. Example below.

  4. Save it as SKILL.md in your OneDrive skills folder

    One folder per skill, named the same as the skill. Then hit Refresh in Manage skills so Copilot picks it up.

  5. Test it on a messy real workbook, then share it

    Your tidy sample won't find the problems. Once it holds up, pass the folder to the team — they drop it in their own OneDrive and use it.

Example — skills/variance-analysis/SKILL.md

---
name: variance-analysis
description: Builds our monthly actual-vs-budget variance bridge with a
  materiality flag and a blank commentary column. Use when someone asks for
  variance analysis, budget vs actual, or to explain the gap on a P&L extract.
---

# Variance analysis

## Steps
1. Find the Account, Actual and Budget columns by their headers.
   If one is missing, ask me — do not guess and do not look in other sheets.
2. Confirm which period we're reporting before calculating anything.
3. Variance = Actual − Budget.  Var % = Variance / Budget (blank if Budget is 0).
4. Flag any row over 50,000 AND over 5%.

## What the finished sheet looks like
- A new sheet named "Variance Bridge — <period>". Never overwrite one.
- Columns: Account | Actual | Budget | Variance | Var % | Flag | Commentary
- Negatives in red brackets, percentages to one decimal, header row frozen.
- Leave Commentary empty — the preparer writes it, not Copilot.

## Don't
- Don't invent accounts or periods that aren't in the source data.
- Don't write the commentary.
- Don't reorder the accounts.
Read it backIf you handed that file to a new starter, could they produce the schedule correctly? If yes, Copilot can too. If no, the file needs another line — not a cleverer prompt.

What we do in the meantime

We can get most of the benefit today with a shared prompt playbook. It's the same content a skill would hold — we just paste it in ourselves instead of Copilot loading it automatically.

  1. Start one shared document — the prompt playbook

    A single Word or OneNote file in the team's Teams/SharePoint folder. One page per recurring task. That file is the future skills library; nothing has to be rewritten later.

  2. Write each entry in the same three-part shape

    Steps · What the finished sheet looks like · Don'ts. Using that structure now means each entry becomes a SKILL.md by copy-paste when the feature arrives.

  3. Paste the whole entry into the Copilot pane before you ask

    Give Copilot the procedure first, then the request. It's two extra seconds and it's the difference between a consistent schedule and a surprise.

  4. Save the ones that work in Copilot Prompt Gallery

    Copilot Chat lets you save and reuse prompts under Your prompts. Excel's pane doesn't have its own save button yet, so the shared document stays the source of truth.

  5. Keep using templates and check the changes

    A locked template workbook still enforces layout better than any prompt. And review what Copilot changed before you save — that habit matters more, not less, once skills arrive.

5

Getting ready — what to do this month

Small, concrete, and all of it useful whether the feature lands next month or next year.

  • Everyone names one task they'd hand over first. That list tells us what to write up.
  • Write up the top three in the steps / finished-sheet / don'ts shape, into the shared playbook.
  • Agree our formatting standard — number formats, header style, sheet naming. Skills can only enforce a standard we've actually written down.
  • Tidy the recurring exports. Consistent sheet and column names are what make any of this reliable; unpredictable headers break skills and people equally.
  • Ask IT where we sit on Microsoft 365 Copilot licensing and the skills rollout, so we know roughly when to expect it.
The one-line takeawayThe hard part of a skill isn't the technology — it's writing down how we actually do the work. We can do that today, and it pays off either way.
